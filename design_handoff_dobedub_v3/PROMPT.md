# 전달용 프롬프트

## 사전 준비

내려받은 `design_handoff_dobedub_v3` 폴더를 로컬 작업 디렉토리 `comfyui-video-studio-app-v4` 루트에 통째로 두십시오.

```
comfyui-video-studio-app-v4/
├── backend/
├── frontend/
└── design_handoff_dobedub_v3/   ← 여기
```

폴더를 두지 않은 채 프롬프트만 전달하면 문서를 찾지 못합니다. 저장소에 커밋할지 여부는 자유이나, 커밋해두면 이후 작업자가 같은 기준을 공유할 수 있습니다.

아래 내용을 그대로 복사해 붙여넣으십시오.

---

## 1. 착수 프롬프트 (첫 대화에 붙여넣기)

```
DOBEDUB STUDIO v3의 프론트엔드 재설계를 실제 코드에 반영하는 작업이다. 작업 디렉토리는 comfyui-video-studio-app-v4이고, 원본 저장소는 changkyuneun-ux/dobedub_studio_v3 (branch main)이다.

작업 디렉토리 루트의 design_handoff_dobedub_v3/ 폴더에 설계와 지시가 모두 들어 있다. 먼저 이 세 파일을 순서대로 읽어라.

1. README.md — 화면 목록, 각 화면의 의도, 상호작용 규칙, 디자인 토큰
2. TASKS.md — 수행할 작업 리스트. S-01 / A(신규 6) / B(수정 8) / C(화면만 12) / D(결정 완료 4)로 나뉘고 권장 순서와 의존 관계가 적혀 있다
3. CHECKLIST.md — 착수 전, 구현 중, 종료 전 확인 항목

같은 폴더의 .dc.html 파일은 브라우저로 열어 확인할 디자인 레퍼런스다. production 코드가 아니다. 마크업이나 클래스 이름을 복사하지 말고, frontend/src의 기존 React + TypeScript 패턴과 컴포넌트로 다시 구현하라. 색·간격·폰트는 README의 Design Tokens를 따르되 코드베이스에 동등한 토큰이 있으면 그쪽을 우선한다.

이 작업의 성격을 먼저 분명히 한다. **기존 화면을 부분 수정하는 작업이 아니라 UI/UX 전면 재구축이다.** frontend/src의 현재 화면은 이번 설계로 대체된다. 기존 컴포넌트에 기능을 덧붙이거나 스타일만 맞추는 방식으로 진행하지 마라. 자세한 기준은 README.md의 "이 작업의 성격" 절에 있으니 반드시 읽어라.

재사용할 것은 로직(API 호출, 상태 관리, 유효성 검사, 폼 훅)이고, 재사용하지 말 것은 화면 구조와 스타일이다. 기존 컴포넌트를 쓸지 판단이 서지 않으면 설계 파일의 해당 화면과 나란히 놓고 보아 같아 보이지 않으면 다시 만들어라.

작업 원칙:
- TASKS.md의 D 절 4건은 이미 결정된 사항이다. 다시 검토하거나 대안을 제시하지 말고 그대로 구현하라.
- 한 번에 한 작업 ID만 처리하고, 그 단위로 커밋한다. 커밋 메시지 앞에 작업 ID를 붙여라 (예: `B-01: 이력 페이지 크기 20으로 통일`).
- 설계 파일에 "미구현" 배지가 붙은 영역은 코드에 저장 기능이 없어 의도적으로 비워둔 자리다. 임의 데이터로 채우지 마라.
- 화면의 예시 데이터(이름, 프롬프트 문구, 수치)는 전부 실제 API 응답으로 교체한다.
- 공통 골격(사이드바 212px, 헤더, 본문 그리드, 우측 패널)은 화면마다 새로 짜지 말고 레이아웃 컴포넌트 하나로 만들어 전 화면이 공유하게 하라.
- 설계에 없는 기존 UI 요소를 임의로 남기지 마라. 남겨야 한다고 판단되면 남기지 말고 먼저 물어라.
- 설계와 코드가 어긋나면 코드가 정본이다. 임의로 맞추지 말고 무엇이 어긋났는지 보고하라.

먼저 세 문서를 읽고, 현재 저장소 상태와 대조한 뒤 다음을 보고하라. 코드는 아직 수정하지 마라.

- 이 문서가 작성된 2026-08-09 이후 backend/app/db/models.py, 마이그레이션(현재 최신 0011), ui_permission_resources 시드에 변경이 있는지
- TASKS.md의 작업 중 이미 처리되었거나 전제가 달라진 것이 있는지
- 첫 착수 대상인 S-01과 B-06을 어떤 순서로 진행할 계획인지
- 현재 frontend/src의 화면 구성이 이번 설계와 어떻게 다른지, 어느 컴포넌트를 걷어내고 어느 로직을 살릴 것인지

보고를 받은 뒤 착수 승인을 하겠다.
```

## 2. 작업 단위 프롬프트 (항목마다 반복)

```
TASKS.md의 [작업 ID]를 진행하라.

시작 전에 해당 항목의 체크박스와 완료 기준을 다시 읽고, 관련 화면 id를 설계 파일에서 확인하라.
구현 후 CHECKLIST.md의 해당 절을 스스로 점검하고, 무엇을 확인했는지 항목별로 답하라.
완료 기준을 충족하지 못했다면 무엇이 남았는지 명시하라.
```

## 3. B-06 전용 프롬프트 (4단계로 나눠 진행)

B-06은 카탈로그 전체를 신형 계층으로 옮기는 작업이라 단계마다 끊어야 합니다.

```
TASKS.md의 B-06 중 [n단계]만 진행하라. 다음 단계로 넘어가지 마라.

이 작업은 3단계까지 기존 동작이 깨지지 않아야 한다. 각 단계를 마치면 다음을 확인해 보고하라.

- 1단계(이관 마이그레이션): 이관된 용어 수, 미대응으로 "기타" 서브카테고리에 수용된 수, 유실 0건 여부, 다운그레이드 경로 동작
- 2단계(읽기 전환): 전환 전후로 GET /api/prompts/catalog가 같은 용어 집합을 반환하는지, generate_prompt의 used_term_ids가 term id인지 keyword id인지 확정한 결과
- 3단계(쓰기 전환): 구형 prompt_terms에 신규 행이 생기지 않는지
- 4단계(정리): 구형 테이블을 참조하는 코드가 남아 있지 않은지
```

## 4. 종료 프롬프트

```
작업을 마무리한다. CHECKLIST.md의 "종료 전" 항목을 전부 점검하고 결과를 보고하라.

역할 4종(SUPER_ADMIN, ADMIN, OPERATOR, VIEWER)으로 각각 로그인해 메뉴 노출과 403 동작을 확인한 결과를 포함하라.

설계와 달라진 부분이 있으면 design_handoff_dobedub_v3/ 폴더가 아니라 프로젝트 문서에 기록하라. 핸드오프 패키지는 전달받은 원본 그대로 둔다.
```
